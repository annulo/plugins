# X 渠道：设计决策

X（Twitter）的代码在 `local/x.ts`、`local/_x_spec.ts`。这里记下为什么这么做，改之前先看。

## 用本机浏览器，不用 X 的开放接口

X 的 API 要付费申请，普通用户拿不到。和小红书一样，用 Annulo 的 `ctx.browser`：用户在弹出的窗口里登录，登录态只留在这台电脑的浏览器 profile 里（`social_accounts.browser_profile`）。

- 读数据靠监听页面自己发的接口（`b.listen`），不解析 DOM，因为接口的字段比页面结构稳定。
- 操作（发推、删推）靠 `data-testid` 选择器。它不随界面语言变化，文字只在「删除」菜单项上用到，中英文都认。
- 接口名和选择器集中写在 `local/x.ts` 开头的 `API`、`SEL` 常量里，X 改版时只改这里。

2026-09 已经改过一次：主页推文列表的接口从 `UserTweets` 改名成了 `UserOriginalsTimeline`，现在两个名字都认。

## 各平台共用一套表

- 推文存进 `social_posts`，和笔记放在一起，状态流转也一样（待审核 → 通过 → 发布 / 排期）。三处含义不同：
  - `title` 不发出去，只是后台列表里给运营看的标题（X 没有标题）；
  - 发出去的是 `body`，`tags` 以 `#话题` 的形式接在最后；
  - `comments` 存回复，`shares` 存转发 + 引用，`collects` 存书签。
- 页面按钮统一调 `social.*`（`local/social.ts`），它按账号的平台转给 `xhs.*`、`x.*`……
- 加新平台：写 `local/<平台>.ts`，在 `local/_platforms.ts` 里加一行（见 PLUGIN.md）。

## 规格和频率

- 字数按 X 的算法算：拉丁字母算 1，中日韩文字和 emoji 算 2，链接一律算 23，上限 280（没考虑付费账号的长推文）。页面和本机函数用的是同一套规则。
- 话题最多 3 个，图片最多 4 张。生成推文时只取文章里的第一张图。
- 频率：两条之间至少隔 30 分钟，一天最多 10 条。比小红书（2 小时、3 篇）宽松，但新号连发还是会被当成机器人。
- 内容有链接（`save` 的 `url`，模板的取数函数给的）时，接在推文最后，给网站引流。

## 发布防重复

发布前把状态改成 `publishing`，同时记下 `claimed_at`。上次中断过的（状态是 `publishing` 或 `failed`），先读一遍主页，按正文比对（去掉链接、话题和空白），找到就直接记成已发布，不再发一次。X 本身也会拒绝内容完全一样的推文，报错会翻成「内容重复」。

## 采集：最多翻 10 页，合计按增量算

- 每次采集最多翻 10 页（约 250 条），最坏两分钟出头。推文上万条的账号也不会一直滚。更早的推文互动数字基本不再变化，停在最后一次读到的值。
- 滚动前先等新的一页渲染出来，再滚几次：滚得太早，页面底部位置没变，不会触发加载。
- 查重按推文 id 一条条查（`where: { channel_id, post_id }`），不一次拉出账号的全部推文。`ctx.db.query` 一页最多 1000 行，只取一页的话，推文多了会漏，漏掉的会被重复插入。
- 账号每天的合计（`social_daily`）按增量算，上一次的合计存在 `social_accounts.metric_totals`：
  - 读到的旧推文，加上「这次的数 − 表里上次的数」；
  - 新推文，整条加上，`posts` 加 1；
  - 没读到的推文，保持不变。

  为什么不直接加总这次读到的推文：最老的推文被挤出这 250 条的范围后，合计会突然变小，渠道页算出的增量就成了负数。为什么不每次加总全表：推文多的账号每次都要翻很多页。第一次采集还没有 `metric_totals`，把表里已有的推文用 `cursor` 翻页读完，算个起点。
- 每条推文每天一行（`social_post_daily`，写法在 `local/_snapshot.ts`，和小红书共用），账号每天一行合计（`social_daily`）。渠道页的「按时间段算涨了多少」和趋势图对两个平台都能用；单篇的增量用 `ctx.db.aggregate` 在平台上算（`local/social_stats.ts`）。

## 已知的限制

- `ctx.db.query` 一页最多 1000 行，超过的要用 `cursor` 翻页。只是要合计的话，用 `ctx.db.aggregate` 在平台上算，不用翻页。
- 用 `x.remove` 删掉的推文，状态改回 `rejected`，但它的数字没从 `metric_totals` 里减掉。在 X 上直接删的推文，表里也不知道。这两种情况合计都会偏大一点。
- 后台打开浏览器用的是 headless 模式。如果被 X 识别（登录后一直跳验证），把 `openBrowser` 改成 `offscreen: true`。
