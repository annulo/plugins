# 社媒自动化的做法

2026-10-19 定。社媒发布、删除靠操作平台网页，平台几天一改版，还有 A/B 测试（每个用户看到的页面不一样）：把每一步写死成选择器，修不完（经过见 `publish-breakage.md`）。
这篇写我们现在怎么做、为什么这么做，接新平台、修老平台都照它来。Annulo 这边的原语见 Annulo 仓库的 `docs/browser-agent.md`。

## 一、AI 看页面做事，脚本当它的工具

| | 谁做 | 为什么 |
|---|---|---|
| 认页面：哪个框是标题、按钮在哪、多了什么弹窗、少了哪一项 | AI（`b.agent`） | 页面会变，只有当场看的能跟上 |
| 决定先做什么后做什么、处理没预料的弹窗和多步流程 | AI | 同上 |
| 打开页面、检查登录的是不是这个账号 | 脚本 | 确定的事，快、不花钱 |
| 上传文件、往富文本框里填字并读回核对、加话题 / 标签、等上传完、读平台接口 | 脚本的工具 | AI 做不了（选文件）或做不稳（富文本直接打字会重复、插错位置） |
| 收不回来的那一下：发布、确认删除 | 脚本的工具，核对过才点 | AI 点不到（`avoid`），出错的代价太大 |
| 判断发没发出去、删没删掉 | 脚本读平台接口 | 页面上的字不可靠 |

插件写的是「要做成什么样 + 验收标准」（任务说明、工具、要传的文件、不许点的按钮），不写每一步怎么点。B站、知乎、抖音已经这么做了（`local/bilibili.ts`、`local/zhihu.ts`、`local/douyin.ts` 的 `publish`、`remove`）。

## 二、几条原则

1. **每一项都读回来核对，按平台真正认的东西核对。** 填完把值从页面读回来逐字比对；话题要核对「变成话题块了没有」，不是「文字里有没有 #话题」（抖音只认点选出来的话题块）。
2. **分两级：必须对的、尽量做的。** 必须的（视频、标题、正文、用户选的封面、平台必填项）不对就不发；尽量做的（话题、标签）没做成照发，结果里带 `warnings`，账号卡片上列出来。
3. **最坏的结果是「没发出去」，不是「发出去一条错的」。** 拿不准就停下，把填好的窗口交给人（`b.show()`），人点发布后照常记下；人晚点自己发了，采集按标题把它对上那条失败记录。
4. **收不回来的事只经工具。** 发布、确认删除写进 `avoid`；工具先核对（标题正文对不对、是不是确认框里的确认按钮），对了才点，点完读接口确认结果。
5. **记忆是笔记，不是重放。** 成功了不记「点了哪些元素」（页面变了照着点会点错），只记这个页面的规律：字段怎么认、用哪个工具、坑和变化（带日期）。插件自带 `notes/<平台>.<操作>.md`，项目学到的在 `user/notes/social/`，人能看能改。
6. **笔记写规律，不写一次的经过，也不为单次事故打补丁。** 「搜索框不认 BV 号」「⋮ 要悬停才出菜单」是规律；「这次选错成了含虚构演绎内容」不是，原因在别处（编号对不上），去修原因。
7. **问题先往通用能力上修。** 遇到卡住先问：别的网站会不会也这样？会的就修 Annulo 的原语（见下面的例子），不在插件里绕。
8. **用模型商原生的函数调用，选会推理的模型。** 动作都是工具，模型直接回结构化调用，比让它写 JSON 稳得多；便宜的小模型主导整件事会回乱、兜圈。设置里「浏览器助手用的模型」选能推理的，不思考也够。
9. **在真实账号上演练，不真发。** `publish({ dry_run: true })`、`remove({ dry_run: true })` 走到最后一步前停下，返回哪些不对和现场截图。改完脚本、改完笔记都用演练验证。
10. **看得见。** 进度里是 AI 每一步的那句话；发布卡片「过程」里能看每一步用了多久，最后是总耗时和 token（模型、输入、输出、缓存）。慢了、贵了一眼能看出卡在哪。

## 三、给一个平台接上 b.agent

1. 脚本做确定的部分：打开页面、检查登录账号、`b.listen` 平台的结果接口。
2. 写任务说明：每一项要填成什么（内容原样给出）、哪些用工具、最后用哪个工具收尾。不写选择器、不写「先点哪里」。
3. 工具（带参数 schema，编号用 integer）：
   - 富文本填写并读回核对（平台的编辑器 AI 直接打字会乱）；
   - 话题 / 标签（要等平台校验、要删平台自动加的）；
   - 等上传完（读整页文字，不靠进度条的 class）；
   - 收尾：发布 / 确认删除——核对、点、读接口，成功返回 `{ finish }` 直接结束；演练时核对完返回 `{ finish }` 不点。
4. `files` 只放要传的文件；`avoid` 放收不回来的按钮文字。
   **元素编号每看一次页面就重排**：工具收到的编号只在这一次调用里有效。要在后面的工具里再用这个元素（比如 `fill_body` 填的编辑框，`publish` 时还要核对），当场给它打一个自己的标记（`data-annulo-body`），之后认标记。
   **能重复调用的工具要能重来**：填正文这类先清空再填，AI 重试时不会贴两遍。
5. 结果：接口拿到 id 就记成功；AI 没做完或平台不收，交给人（`b.show()`），等人点；后台定时任务调不出窗口就报错，写清楚卡在哪。
6. 写初始笔记 `notes/<平台>.<操作>.md`：页面的规律、坑（从 `publish-breakage.md` 和脚本注释里整理）。
7. 用 `dry_run` 在真实账号上演练，看「过程」里的每一步、耗时、token。

## 四、调试：看现场，不猜

- 失败、演练都存现场（`snapshot`）：`shot.png` 截图、`outline.txt` 可操作元素、`page.html` 源码。先看截图确认停在哪，再去源码里找那个元素长什么样。
- 设置 → 模型 → 浏览器助手打开调试，每一步发给模型的页面和它的回复写进运行日志（`annulo logs`）。看模型「看到了什么」，比猜它为什么不点快得多。
- 本机函数在后台跑卡住时，可以用 Chrome 调试端口（profile 目录的 `DevToolsActivePort`）只读地看页面状态、截图。

## 五、这次踩过、修在哪一层

| 现象 | 根因 | 修在 |
|---|---|---|
| 抖音简介整段重复、夹在原来的字中间 | `b.type` 先点编辑框中间，Slate 按点的位置插字 | 插件：粘贴后读回核对；不点编辑框 |
| 抖音话题没加上，核对也查不出 | 粘贴的 `#话题` 只是文字，要从候选点选才变话题块 | 插件：点选候选，核对话题块 |
| B站「自制」找不到 | 投稿页去掉了这一项 | AI 看页面跳过；笔记记下 |
| 小模型回乱码、一次回好几轮、兜圈 | 让模型在文字里写 JSON | Annulo：函数调用；防兜圈（同样的动作同样的页面第 3 次就停） |
| 下拉选成了旁边那一项 | 点开下拉后编号变了，按旧编号点 | Annulo：`select` 按选项文字选并读回 |
| AI 以为按钮不见了、滚动去找 | 弹窗关闭动画中途就看页面 | Annulo：动作后等页面稳定再看 |
| 「⋮」悬停也不出菜单 | 纯图标、没有 href 的 `<a>` 不在元素清单里；`:hover` 要真的移鼠标 | Annulo：收纯图标按钮（图标 class 当说明）、`hover` 真移鼠标 |
| 问模型卡住不回 | 没有超时 | Annulo：每次 90 秒、重试一次 |
| Annulo 重启后浏览器起不来、多出空白窗口 | 后台启动的 Chrome 残留，占着账号目录 | Annulo：打开账号浏览器前关掉残留的 |
| B站 搜 BV 号搜不到 | 搜索框只认标题 | 笔记 |
| 知乎正文核对说「不对」，AI 重填后越来越乱 | 工具记的是元素编号，下一轮编号重排指到了别的元素；重填前没清空 | 插件：给编辑框打标记，重填先清空；写进第三节 |
| 删除时要拖滑块 | 平台风控 | AI 交给人（`ask_user`） |
| 抖音删作品兜圈：去筛日期、搜索，认不出是哪一条 | 卡片标题是纯文字，AI 只看到两个一样的「删除作品」 | Annulo：看页面时列出列表的行（行里的标题、日期），元素标 `row=<n>` |
| 抖音发布按钮核对永远不过 | `<button>.value` 是空串，`??` 不会退到 innerText | 插件：按钮读 innerText（测试抓到的） |

## 六、接下来

- 小红书改成 `b.agent`（话题点选、富文本核对做成工具）。X、LinkedIn、Facebook、Instagram、YouTube 也按需迁。
