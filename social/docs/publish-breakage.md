# 社媒发布卡住的 case 和原因

社媒发布靠本机浏览器操作平台网页（`local/<平台>.ts`），平台一改版就卡，而且一卡就要修很久。
这份文档把卡住的 case 记下来，分析为什么总是修得慢，给以后定更好的方案用。新的 case 加在「case」一节最上面。

## case

### 2026-10-17 X：视频推文发出去了，却报「发布确认失败」

**经过**：同一条科普视频（4 分 09 秒）发 X。视频传完、点了 Post，0.5 秒后报 `发布确认失败：发布结果尚未确认，请先查看账号主页后重试`，帖子标成失败。
其实推文已经发出去了（08:07:01）。之后采集又把它当成平台上的另一条推文记了一笔，同一条推文变成一条「失败」加一条「已发布」。

**原因**：脚本点 Post 后等发推接口的响应，监听写的是 `/Create`。点完 3 毫秒，页面里 Grok 的 `CreateCheckoutSession` 先返回，也含 `/Create`，
`b.responses(..., { min: 1 })` 拿到这一条就返回了。里面没有推文 id，脚本马上跳去主页核对，把还在提交的视频推文打断（或者主页上还没出现），就报失败了。

**改法**（`local/x.ts`）：只认 `CreateTweet` / `CreateNoteTweet`，没等到就接着等（视频最多 3 分钟）；去主页核对前先等发推框关掉，主页上多读几次。

**教训**：
- 监听接口的关键词太宽，页面上别的请求一样能匹配。等「至少 1 条」只适合关键词足够准的时候；
- 「结果没确认」时脚本自己离开了页面，把一个正在成功的操作打断了，又报成失败。结果不确定时，先等页面自己结束，再去别处核对；
- 报错说「请先查看账号主页后重试」，用户照做重试的话，就会发两条。

### 2026-10-17 B 站：投稿页改版，修了近半小时、跑了 14 轮

**经过**：项目「测试自媒体」里，助手做完一条 4 分钟的科普视频（1080p，约 290MB），用插件的 `social.publish` 投 B 站。
从第一次投稿（13:48）到投成功（14:15，BV12wJv64EqW）将近 30 分钟，中间投稿和探测脚本一共跑了 14 次，每次都要重新打开投稿页、重新上传视频。

| 时间 | 做了什么 | 结果 |
|---|---|---|
| 13:48 | 第 1 次投稿，分区「知识 / 财经商业」 | 失败：`分区里没有「财经商业」，可选的有：知识` |
| 13:49 | 分区改成「知识」，第 2 次投稿 | 失败：`这些标签没加上：（10 个全部）（可能是敏感词或 B站 不认）` |
| 13:52–13:57 | 助手写临时探测脚本看创作声明和标签，跑了 3 次 | 3 次都卡在「等标题输入框出现，等了 120 秒」：视频选了没反应 |
| 13:59–14:01 | 改了标签的等待，第 3 次投稿；再开着浏览器窗口第 4 次 | 两次都是 `选了视频，但没出现填写标题的表单` |
| 14:02 | 助手改用第三方命令行 catbus 投稿 | 用户打断：「不要用 catbus，还是应该修复我们自己的发布脚本」 |
| 14:04–14:07 | 再写探测脚本（3 次），看到上传、创作声明下拉的真实结构 | 定位到上传时机和声明选项 |
| 14:09 | 不再清空输入框，第 5 次投稿 | 失败：后 4 个标签没加上（名额被自动标签占了） |
| 14:10 | 删自动标签，第 6 次 | 还是删不掉：关闭按钮是 SVG，`.click()` 无效 |
| 14:11 | 改成派发点击事件，第 7 次 | 失败：「知识分享」B 站不收 |
| 14:14 | 换成「科普」，第 8 次 | 失败：`点了「立即投稿」，但没看到投稿成功`（封面必填，空着） |
| 14:15 | 自动选推荐封面，第 9 次 | 成功，用时 77 秒 |

**原因和修法**（都在 `local/bilibili.ts`）：

| 现象 | 真实原因 | 改法 |
|---|---|---|
| 分区选不上 | 投稿页分区只剩一级，没有「财经商业」 | 第二级找不到就停在第一级；`tasks/write-bilibili.md` 改成只写一级 |
| 视频选了没反应（时有时无） | 投稿页是后加载的子应用（micro-app），文件塞得太早，页面还没挂上监听 | 等 4 秒再传；20 秒没出表单就关弹窗再传一次 |
| 10 个标签全没加上 | 每个标签填之前 `b.type(..., { clear: true })`：输入框是空的时候「清空」会按退格，把上一个刚加好的标签块删了 | 不清空；每个标签等 B 站「请求校验」完、变成标签块再填下一个 |
| 后几个标签没加上 | B 站按分区和标题自动加 5 个左右标签（原创、短片、搞笑……），10 个名额被占 | 先删掉不在我们列表里的，填的过程中名额满了再删 |
| 自动标签删不掉 | 关闭按钮是 `<svg class="close">`，SVG 元素没有 `click()` 方法 | 派发 `MouseEvent('click')` |
| 某个标签加不上 | 「知识分享」B 站不收 | 内容问题，换标签（报错原样告诉用户） |
| 点了投稿没反应 | 新增两个必填项：创作声明、封面 | 创作声明自动选「含AI生成内容」，认不出就停；封面空着就选推荐的第一张，选不上就停 |

**花时间的地方**：一次只暴露一个问题（分区 → 标签 → 上传 → 标签 → 标签 → 标签 → 封面），每次要重新上传 290MB；报错猜的原因好几次是错的（「可能是敏感词」「视频格式 B站 不认」「页面上可能有没填的必填项」）；
助手中途绕去用 catbus，用户打断才回来；探测脚本在同一个 120 秒等待上连续失败 3 次才换思路。修好的代码只在这个项目里，插件仓库是 2026-10-17 才从项目搬回来的。

## 为什么总是修得慢

1. **发现得太晚**。每天的自检（`probe`）只走到「打开投稿页、找到选文件的入口」，不上传、不填表、不提交。
   所以表单里的改动（新的必填项、标签框的行为、分区层级）自检永远看不到，总是在用户真要发的那一刻才撞上，而用户那时候正等着。
2. **一次只暴露一个问题**。脚本按顺序填，第一处不对就抛错。B 站这次 6 处改动，就要撞 6 次墙；每次从头开页面、重新上传大视频，一轮 1～3 分钟。
3. **报错在猜原因，猜错了把人带偏**。「可能是敏感词」其实是输入框把标签删了；「视频格式 B站 不认」其实是传早了；「可能有没填的必填项」没说是哪项。
   页面上明明有红字提示，脚本没读出来。
4. **同样的浏览器坑在不同平台反复踩**。SVG 点不动、`clear` 会按退格、富文本编辑器（Lexical、Quill）清不空、子应用后加载、多选下拉要收起、逐字输入丢字。
   每次都是助手现场翻 `page.html` 重新发现，没有一份「常见坑」让它先查。
5. **修好的代码回不到插件**。`fix-platform` 任务改的是项目里的插件副本（`plugins/social/local/`），插件升级时三方合并。
   别的项目、别的用户还是旧代码，下次再修一遍；这次的修复如果没人手动搬回插件仓库，就只活在一个测试项目里。
6. **只能真发来验证**。没有「填完整个表单、不点提交」的演练，改完只能真投稿看结果，在真实账号上试错。
7. **助手容易绕路**。卡住时先想换个工具（catbus）把这次发出去，而不是修脚本；探测失败后没先缩短超时、换个观察方法，在同一个 120 秒等待上耗了 6 分钟。

## 可以怎么改（待讨论）

按上面的原因对应，前几条收益最大：

1. **发布演练（dry run）**：`publish` 加一个只填不提交的模式，走完上传、标题、分区、标签、声明、封面，停在「立即投稿」前，**不抛错，把每一步的结果和页面上的校验提示汇总成一份报告**。
   - 自检每天用一个几秒的测试视频跑一次演练，改版提前发现、提前修，不等用户发的时候；
   - 修脚本时用演练验证，一轮看到所有问题，不在真实账号上试。
2. **报事实，不猜原因**：失败时读出页面上的提示文字（必填项红字、toast、平台返回的 message）原样报出来；拿不准原因就只说看到了什么。
3. **浏览器常见坑沉淀下来**：先写进内置 skill 的 `browser.md`（一节「常见坑」：SVG 点击、`clear` 的副作用、富文本编辑器、后加载的子应用、弹窗遮挡），
   能做进原语的做进 `ctx.browser`（比如 `b.click` 碰到 SVG 自动派发事件、`b.upload` 后确认页面接住了文件）。这是 Annulo 的改动，要先商量。
4. **修复回流到插件**：`fix-platform` 修通以后，提示用户「这个修复要不要交回插件」；或者 Annulo 发现项目里的插件文件和插件版本不一样时，在设置里列出来。
   目标是一个人修过，所有项目升级都拿到。
5. **失败后从断点续**：失败时窗口已经留着，下一次可以接着这个已上传好视频的页面填，不重新上传。
6. **B 站接浏览器助手兜底**：Instagram、Facebook 已经在找不到按钮时请浏览器助手（`b.act`）帮一步，B 站、抖音、小红书还没接。
7. **任务说明里写清楚**：发布卡住就修插件脚本，不换第三方工具发；探测同一处失败两次就换方法。
